# Base Station Sites

Mobile network teams often refer to a base station location simply as a **site**. The location may be a rooftop or a ground-based installation containing radio equipment, antennas, power equipment, and supporting infrastructure.

In this API, a site record represents a solar-powered mobile network base station site. The record identifies the location and stores the information needed to manage it through the API.

## Site Identification

The API uses two identifiers for each site:

- `id` is the database identifier generated by the API.
- `site_code` is the operational identifier assigned to the base station site.

The `name` field is a descriptive label, not an identifier. Site names do not need to be unique and can change without changing the identity of the site.

| Field | Purpose | Unique | Update allowed |
|---|---|---:|---:|
| `id` | Identifies the database record | Yes | No |
| `site_code` | Identifies the site in the operational environment | Yes | No |
| `name` | Provides a readable name for the site | No | Yes |

Clients use the generated `id` when they retrieve, update, or delete one site:

```http
GET /sites/1
PATCH /sites/1
DELETE /sites/1
```

The `site_code` must be unique. The API returns a `409 Conflict` response if a client tries to create another site with the same code.

The current API does not retrieve sites by `site_code`. Clients receive the generated `id` in the site response and use that value in requests for an individual site.

## Site Fields

| Field | Type | Description |
|---|---|---|
| `id` | integer | Unique identifier generated by the API |
| `site_code` | string | Unique operational identifier for the site |
| `name` | string | Descriptive name for the base station site |
| `latitude` | number | Site latitude in decimal degrees |
| `longitude` | number | Site longitude in decimal degrees |
| `status` | string | Current operating state of the site |
| `created_at` | date-time | Date and time when the record was created |
| `updated_at` | date-time | Date and time when the record was last updated |

The API generates `id`, `created_at`, and `updated_at`. Clients do not provide these fields when creating a site.

## Site Status

A site can have one of the following status values:

| Status | Meaning |
|---|---|
| `operational` | The site is available for normal operation |
| `maintenance` | The site is undergoing maintenance |
| `offline` | The site is not operating |

If a client does not provide a status when creating a site, the API assigns `operational`.

## Location Validation

The API validates coordinates before storing them:

- latitude must be between `-90` and `90`
- longitude must be between `-180` and `180`

These limits prevent the API from accepting coordinates outside the valid geographic ranges.

## Updating a Site

The current `PATCH /sites/{site_id}` operation can update:

- `name`
- `latitude`
- `longitude`
- `status`

The operation does not change `site_code`. This keeps the operational identifier stable after the API creates the record.

## Current Scope

The current model stores information about the base station site itself. Future milestones will connect sites to solar panels, power readings, and operational alerts.

Those resources are part of the project roadmap and are not included in the current data model.
